# Activity 05 - Prototype Fidelity and Method Selection

[← Session 2](../README.md) · [← Previous activity](04-patterns-ergonomics-and-accessibility.md) · [Glossary](../../../resources/glossary.md) · [Academic readings](../../../resources/academic-readings.md)

**Time:** 13 minutes · **Format:** team decision with short rationale

## Goal

Choose the least costly prototype that can answer the current question with enough realism.

## Step 1 - State the question

Complete one sentence:

> This prototype helps us learn whether **[specific user]** can **[action, perception, interpretation, or decision]** when **[condition]**.

Avoid questions such as “Do users like it?” or “Does the whole system work?”

## Step 2 - Select fidelity by dimension

Choose `low`, `medium`, or `high enough for this question` for each relevant dimension:

| Dimension | Required fidelity | Reason |
|---|---|---|
| Appearance and labels |  |  |
| Interaction sequence |  |  |
| System states and alternatives |  |  |
| Timing and latency |  |  |
| Physical size, reach, and placement |  |  |
| Sensory qualities such as sound, light, or movement |  |  |
| Data realism |  |  |
| Technical implementation |  |  |

## Step 3 - Choose the method

Select paper interface, physical mock-up, Wizard-of-Oz, or a hybrid. Explain why the method represents the required dimensions and omits the rest.

If using Wizard-of-Oz, define:

- what the operator receives;
- which rule the operator follows;
- the allowed response time and possible responses;
- how unexpected input is handled;
- what the participant is told before or after the session.

## Step 4 - Write the decision

> We will use **[method]** with **[required realistic qualities]** to investigate **[question]**. We will deliberately omit **[details]** because they do not affect this question. The main limitation is **[limitation]**.

## Output

A prototype question, fidelity profile, method, operator plan where relevant, intentional omissions, and one limitation.
