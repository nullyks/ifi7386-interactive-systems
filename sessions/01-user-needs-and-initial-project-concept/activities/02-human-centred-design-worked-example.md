# Activity 02 — Human-Centred Design Worked Example

[← Session 1](../README.md) · [← Previous activity](01-interactive-system-think-pair-share.md) · [Academic readings](../../../resources/academic-readings.md)

**Time:** 10 minutes · **Format:** demonstration and whole-class questions

## Goal

See how a technology-led idea becomes a provisional human-centred concept. Distinguish a component, a problem hypothesis, intended value, an interaction loop, and evidence still needed.

## Starting statement

> Let us build something with a CO₂ sensor and LEDs.

Before this can be treated as a project concept, it still needs a specific user, use context, goal or problem, intended human outcome, complete interaction, and evidence that the problem and response matter.

## Worked example

### Primary user

A student working with others in a bookable study room.

### Context

A long group-work session. The occupants are focused on a task. The room may become uncomfortable. Opening a window or taking a break is possible. Reading and interpreting raw environmental data is not the group's primary goal.

### Problem hypothesis

Students may not recognise declining comfort early enough to decide when to ventilate, while repeatedly checking sensor values could interrupt their work.

### Evidence status

This is an initial hypothesis. The team has not yet observed how students notice, discuss, or respond to discomfort in shared rooms.

### Value proposition

> For students in a long shared study session who need to maintain a workable environment without monitoring raw data, a calm and glanceable cue may support a timely group decision to ventilate.

### Interaction loop

| Element | Example |
|---|---|
| User goal | Continue productive group work in a comfortable room |
| Environmental input | A simulated or measured air-quality value changes |
| System state | Comfortable, attention soon, or action suggested |
| Output | A labelled light pattern and a simple web status |
| Feedback | Occupants can perceive the current state and suggested response |
| User action | A student opens the window or proposes a short break |
| Further feedback | The status returns to comfortable after ventilation |

### Prototype question

> Can a first-time user interpret the three states and know what action is suggested without a verbal explanation?

## Demonstration sequence

1. Identify what is missing from the technology-led statement.
2. Reveal the user, context, and problem hypothesis one element at a time.
3. Mark each statement as hypothesis or current evidence.
4. Walk through the interaction loop using rough paper elements.
5. Ask one person to act without coaching while another person changes the state cards.
6. Observe what the person notices, thinks happened, and expects next.
7. Stop before improving the concept and list the evidence needed next.

## Evidence still needed

- How students currently notice and respond to poor air or discomfort
- Whether an ambient cue is acceptable during concentrated work
- Which wording or symbol communicates the state without alarm
- Where the cue could be visible without becoming distracting
- Whether a CO₂ measure is an appropriate proxy for the intended experience
- Whether proposed thresholds and sensing are technically feasible

## Discuss

- Which claims concern users, and which concern implementation?
- Which part of the value proposition could evidence challenge?
- What did the volunteer misunderstand or overlook?
- What should the next contextual inquiry or prototype examine?

## Output

A visible concept chain from user and context through problem, value, interaction, and prototype question, together with an explicit list of assumptions.
