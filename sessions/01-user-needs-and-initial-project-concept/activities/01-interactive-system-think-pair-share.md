# Activity 01 - Interactive System Think–Pair–Share

[← Session 1](../README.md) · [Glossary](../../../resources/glossary.md) · [Academic readings](../../../resources/academic-readings.md)

**Time:** 7 minutes · **Format:** individual reflection → pairs → whole-class synthesis

## Goal

Identify a user goal, input, system response or state, output, feedback the user can notice, and what the user does or understands next.

## Prompt

Name one interactive system you used today.

- What were you trying to achieve?
- What did you or the environment do?
- What did the system notice or receive?
- What changed inside the system?
- What did the system produce?
- How did you know what had happened?
- What did you do or understand next?

## Steps

1. **Think - 1 minute.** Select an example and record short answers.
2. **Explain - 2 minutes.** Partner A explains the interaction loop while Partner B looks for a missing link. Swap.
3. **Select - 1 minute.** Choose the example that makes the interaction clearest or raises the most useful question.
4. **Share - 3 minutes.** Contribute the example to the whole-class map.

Use this sequence:

```text
user goal
  → action or environmental event
  → input
  → state or interpretation
  → output
  → feedback
  → user interpretation or next action
```

## Worked example

| Element | Example |
|---|---|
| System | Stop request system on a city bus |
| User goal | Leave the bus at the next stop |
| User action | Press the stop button |
| Input | Button-press signal |
| System state | Stop requested for the next stop |
| Output | An audible chime and a visible “Stop requested” message |
| Feedback | The passenger can hear or see that the request was registered |
| Next action or interpretation | The passenger waits near the exit and expects the bus to stop |

### Contrast

A printed bus timetable is useful but is not itself an interactive system. It presents information without changing state in response to the person. A digital journey planner becomes interactive when a destination or location becomes input, the service computes a route, and the feedback shapes the next choice.

## Check your example

- Is the user's goal different from the device's function?
- Can the user notice the output and understand it as feedback?
- What state changed inside the system?
- Could the same system succeed in one context and fail in another?
- Does the example show that interaction can use physical action, sound, signals in the environment, or a combination of people and technology?

## Output

A complete interaction loop that can contribute to the class discussion.
