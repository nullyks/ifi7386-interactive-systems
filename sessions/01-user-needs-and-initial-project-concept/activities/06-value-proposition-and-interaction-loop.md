# Activity 06 — Value Proposition and Interaction Loop

[← Session 1](../README.md) · [← Previous activity](05-candidate-idea-screen.md) · [Academic readings](../../../resources/academic-readings.md)

**Time:** 10 minutes · **Format:** team writing and diagramming in shared notes

## Goal

Connect the selected problem to an intended human outcome and define the minimum system boundary for one complete interaction.

## Prompt

State what could become better for the named user in the named context. Then trace the minimum interaction that could produce that change. Label assumptions instead of filling gaps with invented certainty.

## Part 1 — Value proposition

**Time: 4 minutes**

> For **[specific user]** in **[specific context]** who needs to **[goal]**, our concept may help by **[benefit]**, so that **[meaningful outcome]**.

Check the sentence:

- Does it name the user and context?
- Does it describe a benefit rather than a list of features?
- Could user evidence show that the claimed value is weak, different, or absent?
- Does it avoid claiming that the solution is already effective?

## Part 2 — Interaction loop

**Time: 6 minutes**

Record the following elements with arrows between them:

1. user goal;
2. user action or relevant environmental event;
3. input received by the system;
4. interpretation, rule, or state change;
5. output in the physical or digital world;
6. feedback the user can perceive and understand;
7. user interpretation and next action.

Add the interface or touchpoint through which each action or perception occurs. If the output is not understandable feedback, identify what must make its meaning clear.

## Worked example

### Value proposition

> For students in a long shared study session who need to maintain a workable environment without monitoring raw sensor readings, a calm and glanceable cue may help the group decide when to ventilate, so that they can continue their work with less disruption.

### Interaction loop

| Element | Example |
|---|---|
| User goal | Continue focused group work |
| Environmental event | The simulated or measured comfort value crosses a provisional threshold |
| Input | A sensor value enters the system |
| State change | Status changes from “Comfortable” to “Action suggested” |
| Output | The physical indicator changes to a labelled symbol and the web status updates |
| Feedback | A student sees “Open window or take a short break” |
| Interpretation | The room may need ventilation |
| Next action | The student opens the window or asks the group to pause |
| Second input | The measured value later improves |
| Second feedback | The system returns to “Comfortable,” confirming the changed state |

### Assumptions to mark

- The environmental measure corresponds to something users experience as relevant.
- The cue is noticeable without being disruptive.
- The suggested action is possible in the setting.
- The group understands who may act.
- The feedback is not mistaken for a safety guarantee.

## Troubleshooting prompts

- If the proposition names only a product benefit, ask what changes for the person.
- If the loop jumps from sensor to outcome, identify the state change and what the user can perceive.
- If the system produces a light without meaning, explain how a first-time user interprets it.
- If the team adds several paths, return to one complete main loop.

## Output

One provisional value proposition, one complete interaction loop, named interface touchpoints, and visibly marked assumptions.
