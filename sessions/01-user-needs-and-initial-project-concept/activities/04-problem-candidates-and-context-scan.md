# Activity 04 - Problem Candidates and Context Scan

[← Session 1](../README.md) · [← Previous activity](03-team-formation-and-skills-mapping.md) · [Glossary](../../../resources/glossary.md) · [Academic readings](../../../resources/academic-readings.md)

**Time:** 24 minutes · **Format:** individual ideas → team grouping → context analysis

## Goal

Generate several project directions, then describe the user and context before selecting a solution. This prevents the first available gadget or feature from becoming the project by default.

A **context scan** is a short, structured description of the user, task, place, social situation, tools, and other conditions that may affect the interaction.

> [!IMPORTANT]
> Your team must be able to reach at least one relevant user before Session 2. Claims made today are early ideas, not confirmed facts.

## Part 1 - Generate candidates

**Time: 5 minutes**

Working individually, write one possible problem direction at a time. Start with a person, activity, or situation rather than a technology. Generate at least three notes per person.

Useful starting questions:

- Who experiences a recurring difficulty that the team can investigate?
- Which activity contains waiting, uncertainty, interruption, coordination, physical effort, missed feedback, or inaccessible information?
- Where could a physical or sensed input and an output the user can notice form a meaningful interaction?
- Which setting can the team observe safely and ethically?

## Part 2 - Cluster and frame candidates

**Time: 7 minutes**

Combine related notes and produce two or three candidate frames. For each candidate, record:

- primary user;
- specific situation or trigger;
- user goal;
- current breakdown, difficulty, or workaround;
- why the outcome matters to the user;
- how the team could collect evidence before Session 2.

Use this pattern:

> In **[specific situation]**, **[specific user]** needs to **[goal]**, but **[present condition or breakdown]** makes this difficult. We currently believe this because of **[named observation, report, experience, or assumption]**.

## Part 3 - Context scan

**Time: 12 minutes**

For every candidate, identify:

- user characteristics that could affect interaction;
- goal and current task sequence;
- physical environment: space, light, noise, movement, weather, or reach;
- social environment: privacy, shared responsibility, attention from others, or local norms;
- technical environment: connectivity, power, devices, sensors, or existing systems;
- organisational conditions: permissions, schedules, or ownership;
- frequency and trigger;
- current resources, tools, and workarounds;
- important constraints and exclusions;
- what is known, observed, reported, inferred, or assumed.

## Worked example

**Weak idea:** Build a smart light for study rooms.

**Candidate frame:** During long group-work sessions in bookable study rooms, students need to maintain a workable environment without interrupting the discussion, but they may notice poor room comfort only after concentration has already declined. This is currently a hypothesis based on the team's own experience and must be checked with other students.

**Context scan:**

| Dimension | Example |
|---|---|
| Primary user | A student participating in a small group-work session |
| Goal | Continue focused collaborative work |
| Physical | Small shared room, variable ventilation, competing visual information, occupants facing different directions |
| Social | Anyone could act, responsibility may be unclear, and one person may not want to interrupt the group |
| Technical | Power and Wi-Fi may be available; the first prototype can simulate sensing |
| Trigger | The room becomes uncomfortable during a long session |
| Current workaround | Someone comments, checks a number manually, or opens a window based on personal judgement |
| Evidence status | Team experience is not sufficient evidence about the wider user group |

## If the frame is still vague

- If the user is “everyone,” name the person who directly interacts in the main scenario.
- If the statement contains an app, sensor, or feature, remove that word temporarily and state what the person still needs to achieve.
- If the context is broad, add a place, time, activity, trigger, and constraint.
- If user access is vague, name a practical way to arrange one observation or conversation.

## Output

Two or three candidate problem frames and a context scan for each candidate in shared notes.
