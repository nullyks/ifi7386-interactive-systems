# Activity 06 - Hi-Fi Slice and Handover

[← Session 3](../README.md) · [← Previous activity](05-component-stations.md)

**Time:** 15 minutes · **Format:** team decision and exit ticket

## Goal

Choose a small Arduino-based Hi-Fi slice that answers a project question and is feasible to build next.

## Steps

1. Revisit one Wizard-of-Oz observation. State what realistic physical behaviour would clarify that issue.
2. Mark the selected path on the team's architecture and state model.
3. Complete the build decision below. Use exact component names when known; mark open decisions honestly.

| Decision | Team answer |
|---|---|
| User context and trigger |  |
| Input component and pin or interface |  |
| Arduino rule, threshold, timing, and state |  |
| Output and feedback to the user |  |
| Power, driver, and safe stopping needs |  |
| Missing, noisy, or unexpected input response |  |
| Parts that remain simulated |  |
| First bench test and success condition |  |
| Components available and components to obtain |  |

4. State one limitation of the planned prototype and one question the next user test can answer.

## Exit ticket

Complete: **We can implement [specific input → rule → output] on Arduino. We need [component or verification] before building. We will test [observable success condition].**

## Output and preparation for Session 4

Save the build decision, revised diagram or flow, Wizard-of-Oz evidence, circuit or code from today, and a short component list. The next meeting starts from this chosen slice. A working project-specific sketch is welcome; a coherent, safely buildable plan is the required minimum.
